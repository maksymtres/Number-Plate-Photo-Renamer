# Number Plate Photo Renamer

Локальное Python-приложение для автоматического распознавания номера на табличке на фотографии и переименования файлов по этому номеру.

Проект сделан под полевые условия: без облачных API, без обязательного интернета, с запуском на Windows-ноутбуках. Основная задача — сократить ручную вечернюю сортировку и переименование большого количества фотографий после экспедиции.

## Задача

Во время фотофиксации рядом с объектом ставится табличка с номером. После съёмки нужно переименовать фотографии по номеру на этой табличке.

MVP автоматически:

- находит табличку на фото;
- распознаёт номер через OCR;
- нормализует и валидирует результат;
- формирует корректное имя файла;
- переименовывает изображения;
- отдельно помечает сомнительные случаи для ручной проверки.

## Что умеет текущая версия

- работает полностью локально;
- обрабатывает папку с изображениями;
- поддерживает `.jpg`, `.jpeg`, `.png`;
- ищет табличку на фото;
- распознаёт номер через Tesseract OCR;
- поддерживает `dry-run` и `apply`;
- создаёт отчёты `report.csv`, `report.xlsx`, `summary_report.txt`;
- показывает low-confidence и unrenamed кейсы;
- поддерживает Streamlit-интерфейс;
- запускается и локально, и через Docker.

## Поддерживаемый формат номера

Сейчас поддерживается формат:

- от 1 до 4 цифр;
- необязательная латинская буква `a-e` в конце.

Примеры:

- `7`
- `71`
- `18b`
- `4d`

## Правила переименования

### Базовый формат

- `7` → `0007.jpg`
- `18b` → `0018b.jpg`
- `71` → `0071.jpg`

### Повторные кадры одного объекта

Если один и тот же номер встречается несколько раз:

- `0007d.jpg`
- `0007d_1.jpg`
- `0007d_2.jpg`

### Low-confidence

Если OCR дал валидный номер, но confidence низкий, к имени добавляется суффикс `-!`.

Примеры:

- `0018b-!.jpg`
- `0007d_1-!.jpg`

### Невалидные случаи

Если табличка не найдена или OCR-результат не проходит валидацию:

- файл не переименовывается;
- в отчёте фиксируется `status = error`;
- файл попадает в список `unrenamed`.

## Как работает пайплайн

### 1. Детекция
На текущем этапе используется эвристическая детекция таблички через OpenCV.

### 2. OCR
После вырезания области таблички выполняется распознавание текста через Tesseract OCR.

### 3. Нормализация
OCR-результат очищается, нормализуется и проверяется на соответствие допустимому формату.

### 4. Переименование
Для валидных результатов формируется новое имя файла. В режиме `dry-run` создаётся только план переименования, в режиме `apply` выполняется реальное переименование.

### 5. Отчёты
После обработки формируются:

- `report.csv`
- `report.xlsx`
- `summary_report.txt`

## Установка

### 1. Создать окружение

Пример для conda:

```bash
conda create -n graves_cv python=3.11 -y
conda activate graves_cv
```

### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

### 3. Установить Tesseract OCR

На Windows Tesseract ставится отдельно.

Приложение поддерживает 3 варианта поиска Tesseract:

1. через переменную окружения `TESSERACT_CMD`;
2. через `PATH`;
3. через стандартные Windows-пути установки.

## CLI запуск

### Dry run

```bash
python main.py --input-dir input_photos --dry-run
```

### Apply

```bash
python main.py --input-dir input_photos --apply
```

### Дополнительные параметры

```bash
python main.py --input-dir input_photos --debug-dir debug_output --report-dir reports --dry-run
```

Поддерживаемые параметры:

- `--input-dir`
- `--debug-dir`
- `--report-dir`
- `--dry-run`
- `--apply`

## Streamlit UI

Что есть в интерфейсе:

- выбор источника изображений:
  - папка на диске;
  - загрузка нескольких файлов;
- выбор режима:
  - `Dry run`
  - `Apply`
- таблица результатов;
- блок проблемных изображений;
- отдельные списки `Low-confidence` и `Unrenamed`;
- скачивание `CSV`, `Excel` и `summary_report.txt`.

### Локальный запуск Streamlit

```bash
streamlit run app_streamlit.py --server.address 127.0.0.1 --server.port 8503
```

Рекомендуемый порядок работы:

1. сначала `Dry run`;
2. проверить таблицу и проблемные случаи;
3. потом запускать `Apply`.

## Docker запуск

### Важные файлы

В корне проекта должны лежать:

- `Dockerfile`
- `docker-compose.yml`
- `.dockerignore`

Обрати внимание: файл должен называться именно **`.dockerignore`** — с точкой в начале.

### Сборка и запуск

```bash
docker compose up --build
```

После запуска открыть:

```text
http://localhost:8503
```

### Работа с папкой фото в Docker

В `docker-compose.yml` папка `./input_photos` примонтирована в контейнер как:

```text
/data/photos
```

Если в Streamlit выбран режим **Папка на диске**, указывай путь:

```text
/data/photos
```

### Важное замечание

Режим `Apply` реально переименовывает файлы в примонтированной папке. Сначала рекомендуется запускать только `Dry run`.

## Ограничения текущего MVP

- детектор таблички пока эвристический, а не нейросетевой;
- OCR чувствителен к качеству crop, освещению и сложным ракурсам;
- основной фокус пока на `.jpg/.jpeg/.png`;
- RAW и связанные файлы пока не обрабатываются;
- часть сложных кейсов всё ещё требует ручной проверки;
- `Apply` лучше запускать сначала на копии папки.
